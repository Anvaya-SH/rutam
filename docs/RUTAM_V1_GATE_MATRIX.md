## Unreachable or parallel paths

These are reachability findings relative to the primary RUTAMForCausalLM/model-factory forward path. A module can still be a usable separate API.

- model/lfm3_adapter.py and model/layer_integration.py: public exports and synthetic tests exist, but generic `create_model` and `execute_rutam_forward` do not call this adapter. The new `create_lfm3_bridge` is an explicit, separate public route; the adapter remains a parallel synthetic/protocol design.
- model/graph_attention_bridge.py: public export and tests exist, but execute_rutam_forward does not call GraphAttentionBridge; the main path invokes the query head, selector and encoder itself.
- memory/read_pipeline.py: used by RUTAMMemoryController.read_memory, but execute_rutam_forward has its own query/selection/encoding path and does not call read_memory. This is a parallel read implementation whose behavior can diverge.
- recurrent modules and linker/path-prediction modules are separate optional workflows. They are not part of the default graph-native forward acceptance path; the validation report intentionally excludes recurrent/agentic experiments.
- Two classes have the same name but different jobs: graph.attention.RUTAMGraphAttention is graph self-attention used by encoder modes; model.graph_attention.RUTAMGraphAttention is cross-attention used by RUTAMGraphFusion. They are not interchangeable, but the naming collision makes architecture tracing harder.

## Superseded or misleading integration evidence

- tests/test_rutam_compatibility.py::test_lfm3_adapter_integration constructs RUTAMLFM3Adapter around SyntheticBackbone, then passes adapter.backbone (the synthetic backbone itself) to RUTAMForCausalLM. It does not pass the adapter into the model, so it does not prove adapter-to-model integration or LFM3 compatibility.
- tests/test_lfm3_adapter.py::test_adapter_forward_with_graph_fusion uses SyntheticBackbone plus caller-supplied random graph tensors. It proves generic wrapper/hook behavior, not LFM3 layer compatibility.
- tests/test_fusion_integration.py::test_fusion_integration_with_controller_and_training_step creates random hidden states and a separate nn.Linear language head. It bypasses the public backbone/model integration point.
- tests/test_backbone_compatibility.py::test_generic_backbone_attribute_inspection uses MockGenericBackbone for attribute discovery. Its scope is metadata introspection, not a successful LFM3 forward.
- tests/test_lfm3_bridge.py uses locally defined classes with Transformers-like names and signatures. It proves the bridge's structural contract against the double, not compatibility with the installed package or released checkpoint.
- tests/test_v1_end_to_end.py::test_real_lfm3_local_integration does not mock success; it explicitly skips without a local checkpoint and Transformers.
